## 2025-05-15 - [HIGH] Fix overly permissive Firestore write rules
**Vulnerability:** The `firestore.rules` contained multiple collections (`courts`, `matches`) and a collection group (`profile`) with `allow write: if request.auth != null;`. This allowed any authenticated user to create, update, or delete any document in these collections, regardless of ownership.
**Learning:** Defaulting to `request.auth != null` for write operations is a common but dangerous pattern in Firebase apps. It provides a false sense of security by requiring authentication but fails to enforce authorization. Collection group rules are particularly risky as they apply to all collections with that name across the entire database.
**Prevention:** Always use the principle of least privilege. Use `request.resource.data.diff(resource.data).affectedKeys().hasOnly([...])` to restrict which fields can be updated by non-owners. Ensure collection group rules are either read-only or restricted to administrative roles, while using specific paths for user-owned data updates.

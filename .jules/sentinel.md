## 2025-05-14 - Insecure Firestore Security Rules
**Vulnerability:** Overly permissive Firestore rules allowed any authenticated user to write to the `courts` collection and the `profile` collection group. Furthermore, `matches` could be updated by any authenticated user to modify `players` or `score` fields without being a participant in the match.
**Learning:** Granular field-level checks like `request.resource.data.diff(resource.data).affectedKeys().hasOnly(['players', 'score'])` are insufficient if they aren't combined with identity-based authorization. Without checking if `request.auth.uid` is actually a participant or the host, any user could tamper with match results.
**Prevention:** Always pair field-level validation with strict identity-based access control. Ensure that `write`, `update`, and `delete` operations are restricted to the document owner, participants, or administrators. Use `get()` in rules to verify membership in arrays (like `players`) when necessary.
